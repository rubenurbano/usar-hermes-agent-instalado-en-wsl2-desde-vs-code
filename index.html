Usar Hermes Agent instalado en WSL2 desde VS Code

Guía completa para conectar Visual Studio Code (Windows 11) con el Hermes Agent que ya tienes instalado en WSL2/Ubuntu, utilizando el protocolo ACP (Agent Client Protocol). Sin reinstalar, sin duplicar configuración, reutilizando exactamente el mismo agente.

🎯 Objetivo del tutorial

Tenemos la siguiente arquitectura de partida:

Windows 11 │ ├── VS Code │ └── WSL2 / Ubuntu │ └── Hermes Agent

Queremos que VS Code utilice el Hermes Agent que YA tenemos instalado en WSL2.

No vamos a instalar Hermes otra vez en Windows. La comunicación se hará mediante ACP (Agent Client Protocol).

🧭 Cómo navegar este tutorial

  • Verificación: comprobar que Hermes y ACP funcionan en WSL.
  • VS Code + WSL: preparar VS Code para trabajar dentro del entorno Linux.
  • Config ACP: registrar el agente Hermes en ACP Client.
  • Pruebas: validar conversación, archivos, terminal y proyectos reales.
  • Arquitectura / Advertencias / Problemas: consolidar y evitar errores.
  • Fuentes y Créditos: referencias oficiales y datos del autor.

🔍 Verificación previa en WSL

Antes de tocar VS Code, hay que confirmar que Hermes y su soporte ACP funcionan correctamente dentro de WSL2.

1

Comprobar que Hermes funciona en WSL

Acción: abre Ubuntu/WSL y ejecuta:

hermes --version
Prueba
Debe aparecer la versión instalada de Hermes.
Importante
Si aparece command not found, NO continúes. Primero hay que solucionar la instalación de Hermes.
2

Comprobar ACP

En la misma terminal WSL ejecuta:

hermes acp --version

Después:

hermes acp --check
Prueba
Si ACP está correctamente instalado, la comprobación debe terminar sin errores importantes.
Importante
No ejecutes todavía hermes acp y lo dejes funcionando. Ese comando inicia el servidor ACP y queda esperando que un cliente, como VS Code, se conecte.
3

Si ACP no está instalado

Solo haz este paso SI el Paso 2 indica que falta el soporte ACP. Primero localiza la instalación de Hermes:

cd ~/.hermes/hermes-agent

Después instala el extra ACP:

uv pip install -e '.[acp]'

Cuando termine:

hermes acp --check
Prueba
La comprobación debe ejecutarse sin errores.
Importante
Si el Paso 2 ya funcionaba correctamente, NO ejecutes este paso.

🔗 VS Code conectado a WSL

4

Comprobar que VS Code puede trabajar con WSL

En Windows abre VS Code. Instala la extensión:

WSL de Microsoft.

Después pulsa:

Ctrl + Shift + P

Escribe:

WSL: Connect to WSL

Selecciona tu distribución Ubuntu. VS Code se volverá a abrir conectado a WSL.

Prueba
En VS Code abre Terminal → New Terminal. La terminal debe ser una terminal Linux/WSL. Ejecuta: 
which hermes
Debe aparecer la ruta del ejecutable de Hermes. Por ejemplo: 
/home/rubenurbano/.local/bin/hermes
La ruta exacta puede ser diferente.
Importante
No copies esa ruta como si fuera obligatoriamente la tuya. Usa la ruta que devuelva which hermes.
5

Instalar ACP Client en VS Code

En VS Code pulsa:

Ctrl + Shift + X

Busca:

ACP Client

Instala la extensión ACP Client.

Importante
La documentación actual de Hermes indica utilizar ACP Client para conectar Hermes con VS Code.
6

Configurar Hermes en ACP Client

La documentación oficial de Hermes indica esta configuración:

{
  "acp.agents": {
    "Hermes Agent": {
      "command": "hermes",
      "args": ["acp"]
    }
  }
}

Como estamos trabajando dentro de WSL, el objetivo es que ese comando:

hermes acp

se ejecute dentro del entorno WSL donde Hermes ya está instalado.

⚙️ Configuración ACP en VS Code

7

Abrir la configuración JSON de VS Code

En VS Code pulsa:

Ctrl + Shift + P

Escribe:

Preferences: Open User Settings (JSON)

Abre el archivo JSON. NO borres las configuraciones que ya tengas. Añade la configuración de Hermes dentro del objeto JSON existente.

Debe quedar conceptualmente así:

{
  "acp.agents": {
    "Hermes Agent": {
      "command": "hermes",
      "args": ["acp"]
    }
  }
}
Info
Si tu archivo ya contiene otras configuraciones, simplemente añade la propiedad "acp.agents" respetando las comas del JSON.
8

Importante: ejecutar VS Code conectado a WSL

Este paso es importante. Para nuestra instalación NO queremos que Windows intente ejecutar:

hermes

como un programa Windows. Queremos:

VS Code ↓ WSL ↓ hermes acp ↓ Hermes Agent

Por eso debes trabajar con VS Code conectado a WSL mediante:

WSL: Connect to WSL
9

Abrir ACP Client

En VS Code busca el panel de ACP Client. Si aparece en la barra lateral, ábrelo. Debería aparecer Hermes Agent como agente disponible.

Selecciona:

Hermes Agent

Pulsa:

Connect

🧪 Pruebas funcionales

10

Primera prueba

Cuando Hermes esté conectado, escribe algo MUY sencillo:

Mensaje de prueba
Hola Hermes. Responde únicamente: "Hermes está funcionando dentro de VS Code."
Prueba
Debe responder Hermes dentro del panel ACP de VS Code.
11

Comprobar que Hermes puede trabajar con archivos

Ahora vamos a comprobar que no solamente conversa. Crea en el proyecto abierto un archivo:

prueba-hermes.txt

Escribe dentro:

Este archivo ha sido creado para probar Hermes Agent.

Después pídele a Hermes:

Petición
Lee el archivo prueba-hermes.txt y dime exactamente qué contiene.
Prueba
Hermes debería utilizar sus herramientas de archivos y mostrarte el contenido.
12

Comprobar una modificación

Ahora pídele:

Petición
Modifica prueba-hermes.txt y añade al final esta línea:
"Modificado por Hermes Agent desde VS Code."
Prueba
Comprueba físicamente el archivo. Debe contener las dos líneas.
13

Comprobar el terminal

Pídele:

Petición
Ejecuta en el terminal el comando: pwd
Prueba
Hermes debería ejecutar el comando mediante su herramienta de terminal y mostrar el resultado.
Importante
Como Hermes está funcionando dentro de WSL, el entorno de ejecución será Linux/WSL.
14

Comprobar el proyecto real

Ahora abre en VS Code uno de tus proyectos reales. Por ejemplo:

~/proyectos/mi-proyecto

o el directorio que corresponda. Pídele a Hermes:

Petición
Analiza la estructura de este proyecto.

No modifiques ningún archivo.

Dime:
1. qué tipo de proyecto es
2. qué archivos principales contiene
3. qué tecnologías utiliza
4. cuál parece ser el archivo principal
5. qué mejoras detectarías
Prueba
Hermes debe analizar el proyecto sin modificarlo.

🏗️ Entender qué hemos conseguido

15

La configuración final

WINDOWS 11 │ ▼ VS CODE │ │ ACP ▼ WSL2 │ ▼ hermes acp │ ▼ HERMES AGENT │ ├── archivos ├── terminal ├── herramientas ├── memoria ├── skills ├── navegador └── modelos
Ventaja fundamental
NO estamos creando otro Hermes. Estamos utilizando: EL MISMO HERMES QUE YA TIENES EN WSL.

🎁 Resultado final

Cuando todo funcione tendrás:

VS Code │ ├── edición de código ├── archivos ├── terminal ├── Git └── ACP Client │ ▼ Hermes Agent │ ▼ WSL2

Y podrás utilizar Hermes como agente de programación desde VS Code, manteniendo la instalación y configuración de Hermes que ya tienes en WSL.

Nota importante
La documentación oficial actual de Hermes confirma que hermes acp es el servidor ACP para integración con IDEs y que VS Code puede conectarse mediante ACP Client.

⛔ No tocar esto

Paso 16 — Cosas que NO debes hacer inicialmente.

🚫 Lista de cosas prohibidas al inicio

  • No reinstales Hermes en Windows.
  • No copies la instalación de Hermes de WSL a Windows.
  • No cambies de modelo porque sí.
  • No muevas ~/.hermes.
  • No cambies tu configuración actual.
  • No instales cosas adicionales si hermes acp --check ya funciona.
  • No ejecutes hermes acp manualmente mientras intentas conectarlo desde ACP Client.
Recuerda
El objetivo es reutilizar el Hermes que ya tienes. Toda acción que duplique, mueva o reinstale puede romper tu entorno actual.

🛠️ Solución de problemas

Problema 1 — hermes acp --check dice que falta ACP

Síntoma: hermes acp --check dice que falta ACP.

Solución:

cd ~/.hermes/hermes-agent

uv pip install -e '.[acp]'

Después:

hermes acp --check
Problema 2 — VS Code dice que no encuentra "hermes"

Solución: comprueba desde el terminal WSL de VS Code:

which hermes

Si devuelve una ruta, Hermes existe en WSL. Comprueba también:

echo $PATH

El problema probablemente será que el proceso de VS Code no está heredando correctamente el PATH de tu shell.

Importante
NO reinstales Hermes todavía.
Problema 3 — ACP Client aparece pero Hermes no conecta

PRIMERO comprueba desde la terminal WSL de VS Code:

hermes acp --check

Si falla, arregla primero ese problema. Si funciona, vuelve a intentar la conexión desde ACP Client.

Problema 4 — Hermes funciona en terminal Ubuntu normal pero no desde VS Code

Comprueba que VS Code está realmente conectado a WSL. En la terminal integrada ejecuta:

uname -a

y:

which hermes

Si estás dentro de WSL, debería aparecer información de Linux y la ruta Linux de Hermes.
